## Задание 1. Заказ билетов

### Постановка

Программа читает имя покупателя, количество билетов, цену одного билета и признак скидки. Затем она вычисляет базовую сумму, размер скидки и итог к оплате.

Порядок проверок:

1. Прочитать имя целиком, затем три поля: количество, цену, признак скидки.
2. Если чтение не удалось — вывести `Input error`.
3. Если количество не в диапазоне 1–10 или цена не в диапазоне (0; 5000] — вывести `Invalid data` и завершить программу до расчёта.

Расчёт:

- `base = price * tickets`
- `discount = base * 0.10` при наличии скидки, иначе `0`
- `total = base - discount`

### Типы данных

| Данные | Тип | Допустимые значения |
| --- | --- | --- |
| Имя и фамилия | `std::string` | одна строка с пробелами |
| Количество билетов | `int` | от 1 до 10 включительно |
| Цена одного билета | `double` | больше 0 и не больше 5000 |
| Признак скидки | `bool` | ввод 0 или 1 |
| Ставка скидки | `const double` | 0.10 |
| Базовая сумма, размер скидки, итог | `double` | результаты вычислений |

**Почему ставка скидки оформлена константой.** Значение 0.10 — это параметр задачи, который не должен меняться во время работы программы. Константа:

- защищает значение от случайного изменения (компилятор не даст присвоить новое значение);
- заменяет «магическое число» в формуле понятным именем;
- позволяет изменить ставку в одном месте, а не искать число по всему коду.

| 2 | `Test 2`; `2 150.5 0` | 2 · 150.5 = 301; скидки нет | База 301, скидка 0, итог 301 |
| 3 | `Test 3`; `10 5000 1` | 10 · 5000 = 50000; 50000 · 0.10 = 5000; 50000 − 5000 = 45000 | База 50000, скидка 5000, итог 45000 (верхние границы допустимы) |
| 4 | `Test 4`; `0 200 1` | количество 0 вне диапазона | `Invalid data` |

## Задание 2. Серия температур

### Постановка

Программа читает количество показаний (от 0 до 10), затем ровно столько целых температур.

- Показание **допустимо**, если оно в диапазоне от −50 до 100 включительно.
- Показание **рабочее**, если оно в диапазоне от 0 до 40 включительно.

Для каждого показания (цикл `for`):

- вне диапазона датчика: увеличить счётчик отклонённых, вывести `Rejected`, перейти к следующей итерации через `continue`;
- допустимое: вывести `Accepted`, увеличить счётчик принятых, добавить значение к сумме; если оно рабочее — увеличить счётчик рабочих.

После цикла выводятся `Valid`, `Invalid`, `Working` и `Average` (среднее по всем принятым, при их отсутствии — `n/a`).

Количество вне диапазона 0–10 даёт `Invalid count` и завершение до цикла. Ошибка чтения любого поля даёт `Input error`, итоги при этом не печатаются.

### Типы данных

| Данные | Тип | Назначение |
| --- | --- | --- |
| Количество показаний | `int` | число итераций цикла |
| Температура | `int` | очередное показание |
| Счётчики принятых, отклонённых, рабочих | `int` | подсчёт показаний |
| Сумма принятых значений | `int` | сумма температур  (что бы деление давало double использовал static_cast<double>(sum)) |

### Инвариант цикла

После каждой итерации выполняется равенство:

```
прочитано = принято + отклонено
```

Каждое прочитанное показание либо принимается, либо отклоняется — третьего варианта нет. Поэтому после завершения цикла `Valid + Invalid = Count`. Счётчик рабочих показаний в это равенство не входит: рабочие — это подмножество принятых, и всегда `Working ≤ Valid`.

### Ожидаемые результаты (рассчитаны вручную до запуска)

| № | Ввод | Ожидаемый результат |
| --- | --- | --- |
| 1 | `3`, `20`, `50` `101` | Valid 2, Invalid 1, Working 1, Average = (50 + 20) / 2 = 35 |
| 2 | `0` | Valid 0, Invalid 0, Working 0 |
| 3 | `2`; `-51`, `101` | Оба отклонены: Valid 0, Invalid 2, Working 0 |
| 4 | `2`; `0`, `40` | Оба приняты и рабочие: Valid 2, Invalid 0, Working 2, Average = (0 + 40) / 2 = 20 |
| 5 | `2`; `-50`, `100` | Оба приняты, но не рабочие: Valid 2, Invalid 0, Working 0, Average = (−50 + 100) / 2 = 25 |
| 6 | `11` | `Invalid count` |
| 7 | `5`; `5`, `5`, `e` | `Input error`, итоги не печатаются |

### Ответы на вопросы задания

**Почему температура 50 принимается датчиком, но не попадает в рабочий интервал?**
Диапазон датчика — от −50 до 100, поэтому 50 в него входит и значение принимается (`Accepted`). Рабочий интервал уже: от 0 до 40, а 50 > 40. Рабочие показания — это подмножество принятых, поэтому значение может быть принятым, но не рабочим. Это видно в наборе 5: значения −50 и 100 приняты, а `Working: 0`.

**Занимает ли отклонённое показание итерацию?**
Да, одну. Цикл `for` выполняется ровно `Count` раз, а `continue` лишь пропускает остаток тела текущей итерации и переходит к следующей. Подтверждение — набор 3: при `Count: 2` прочитаны оба значения (−51 и 101), оба отклонены, и `Invalid: 2` — итерации не «возвращаются» и не добавляются.

### Выводы по заданию 2

- Подсчёт принятых, отклонённых и рабочих показаний корректен на всех наборах; границы диапазонов (−50, 100, 0, 40) обработаны правильно.
- Среднее считается как `double`, поэтому результат может быть дробным; сумма хранится, счётчики и температуры — в `int`.
- Ошибки чтения (буква вместо числа, нехватка данных) приводят к `Input error` без печати итогов, неверное количество — к `Invalid count` до цикла.
- При отсутствии принятых показаний не выводится `Average`.

## Задание 3. Помощник покупок по бюджету

### Постановка

Пользователь задаёт бюджет, затем по очереди вводит цены покупок. Все суммы — целые рубли, тип `int`.

- Бюджет — от 0 до 100000 включительно, иначе `Invalid budget` и завершение до ввода цен.
- За один запуск можно ввести не более десяти цен (предельное количество хранится в константе); цикл `for` ограничивает число шагов.
- Число `0` завершает ввод (`break`).
- Допустимая цена — от 1 до 100000.

Для каждой цены порядок проверок такой:

1. успешность чтения (иначе `Input error`);
2. сигнал завершения (`0`);
3. диапазон цены (иначе `Invalid price`);
4. достаточность остатка (иначе `Not enough money`).

Если покупка принята — выводится `Added`, остаток уменьшается, расходы и число покупок растут. При любом отказе (`Invalid price`, `Not enough money`) остаток, расходы и количество не меняются, но шаг считается использованным. Покупка, расходующая остаток полностью, разрешена.

После обычного выхода выводятся `Items`, `Spent`, `Remaining`. При ошибке чтения итог не печатается.

### Типы данных

| Данные | Тип | Назначение |
| --- | --- | --- |
| Бюджет | `int` | начальная сумма |
| Остаток | `int` | сколько денег осталось |
| Расходы | `int` | сумма принятых покупок |
| Количество покупок | `int` | число принятых покупок |
| Предельное количество цен | `const int` | 10, ограничение цикла |
| Цена | `int` | очередное введённое значение |

### Инвариант

После каждого шага:

```
бюджет = расходы + остаток
```

Принятая покупка уменьшает остаток ровно на ту сумму, на которую увеличиваются расходы, а отказ не меняет ни то, ни другое. Поэтому сумма расходов и остатка всегда равна исходному бюджету, а остаток никогда не становится отрицательным.

### Контрольный запуск

Ожидаемый результат (рассчитан вручную до запуска):

| Шаг | Цена | Остаток до | Решение | Остаток после | Расходы |
| --- | --- | --- | --- | --- | --- |
| 1 | 70 | 200 | `Added` | 130 | 70 |
| 2 | 50 | 130 | `Added` | 80 | 120 |
| 3 | 100 | 80 | `Not enough money` (100 > 80) | 80 | 120 |
| 4 | 0 | 80 | завершение ввода | 80 | 120 |

Итог: `Items: 2`, `Spent: 120`, `Remaining: 80`. Проверка инварианта: 200 = 120 + 80.

Фактический результат при вводе `200`, `70`, `50`, `100`, `0`:

```

Price (0 stop): 70
Added
Price (0 stop): 50
Added
Price (0 stop): 100
Not enough money
Price (0 stop): 0
Items: 2
Spent: 120
Remaining: 80
```

### Выводы по заданию 3

- Контрольный запуск совпал с ручным расчётом; порядок проверок соблюдается, отказ сохраняет накопленные результаты.
- Связь «бюджет = расходы + остаток» сохраняется на каждом шаге, что позволяет быстро проверять корректность расчёта.
- Для полного подтверждения требований нужно выполнить оставшиеся наборы (границы бюджета, полный расход остатка, `Invalid price`, ограничение в десять шагов, ошибка чтения).
